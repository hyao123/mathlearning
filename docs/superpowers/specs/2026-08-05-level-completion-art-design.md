# 每关完成作品展示设计

## 1. 目标与范围

为每个关卡结算页增加一件与本关合成链对应的“完成作品”展示，增强学生完成关卡后的成就感，同时不改变现有题目、答题、奖励、背包、合成和进度逻辑。

本期范围：

- 6 个章节、每章 12 个关卡均展示独立组件作品。
- 尚未合成时展示蓝图与材料进度，合成后展示成品状态。
- 每 3 个组件展示对应大型部件进度；第 12 关展示章节终极工程预览。
- 复用现有物品视觉系统，增加结算页的作品卡、稀有度边框、完成徽记和轻量扫描效果。
- 移动端、桌面端、低性能模式和减少动画模式均提供可用静态降级。

非目标：

- 不自动合成、不自动消耗材料、不修改奖励发放。
- 不新增商店、装备数值、复杂养成或战斗系统。
- 不批量重绘全部物品资源，不引入外部图片或运行时依赖。

## 2. 作品映射规则

每个章节的 12 个关卡按照既有项目配方的 `componentRecipes` 顺序映射到 12 个组件。映射关系由数据解析，不按章节名称或界面文案硬编码。

每 3 个组件对应一个大型部件：

| 关卡范围 | 展示对象 |
| --- | --- |
| 1–3 | 大型部件 1 的三个组件与部件进度 |
| 4–6 | 大型部件 2 的三个组件与部件进度 |
| 7–9 | 大型部件 3 的三个组件与部件进度 |
| 10–12 | 大型部件 4 的三个组件与终极工程预览 |

组件状态由背包当前数量和合成配方解析：

- `blueprint`：组件尚未合成，显示蓝图、需求材料和当前数量。
- `ready`：材料已满足合成条件但组件尚未合成，显示“可以装配”。
- `completed`：背包中已有组件，显示成品视觉和“作品已完成”。

展示层只读取状态，不调用合成和奖励写入操作。未完成组件不能被结算页标记为已获得。

## 3. 数据接口

新增独立模块 `game/levelArtifactModel.js`，提供纯函数：

```js
getLevelArtifact(chapterId, levelId, state)
```

返回结构：

```js
{
  componentId,
  component,
  status,
  ownedQuantity,
  requiredQuantity,
  partId,
  part,
  partProgress,
  finalProject,
  routeIndex,
  routeTotal
}
```

接口要求：

- 从 `GameItemCatalog.getSuperProject(chapterId)` 解析组件、部件和终极工程。
- 兼容现有章节和后续注册章节，只依赖标准项目配方。
- 缺失章节、关卡或配方时返回明确的空结果/错误信息，不阻塞地图和答题流程。
- 不改变存档结构；作品状态可由当前背包和配方实时推导。
- `routeIndex` 为稳定的 1-based 关卡位置，`routeTotal` 为章节组件数量。

## 4. 结算页体验

现有结算页保留星级、奖励和继续/返回操作，在其间增加“作品揭晓区”：

1. 标题显示“作品解锁：组件名称”。
2. 大图显示组件专属视觉；蓝图状态使用低透明度轮廓和材料进度，成品状态使用彩色成品视觉。
3. 显示稀有度边框、作品状态和“第 X / 12 件作品”。
4. 进度条显示 12 个组件节点，每 3 个节点连接到大型部件节点。
5. 当前组件高亮，已有组件使用已完成样式，未到达组件保持轮廓样式。
6. 第 3、6、9、12 关展示大型部件阶段卡；第 12 关同时展示终极工程蓝图。

奖励区继续负责固定奖励、随机奖励和数量合并，作品区只负责成就展示，避免学生误认为答题直接获得完整成品。

移动端采用单列：作品卡 → 组件路线 → 奖励 → 操作；桌面端采用作品大图与路线双栏布局。主操作仍为“继续下一关”，次操作仍为“返回章节地图”。

## 5. 视觉与性能

- 使用现有 `getItemVisual`/项目专属 SVG 视觉作为来源。
- 作品卡使用章节主题色、稀有度色和统一的深色工程背景。
- 只对当前作品和终极工程预览优先加载视觉，其余节点使用缩略或延迟加载。
- 扫描线、闪光和节点点亮使用 CSS 轻量动画。
- `prefers-reduced-motion: reduce` 或低性能模式下关闭连续动画，保留高对比静态边框和状态图标。
- 图片加载失败时使用现有生成式 SVG 兜底，不能出现空白区域。
- 所有图像具有准确的 `alt`/`aria-label`，蓝图状态不使用“已完成”措辞。

## 6. 测试与验收

单元测试：

- 6 章 × 12 关均能解析唯一组件。
- 每 3 个组件正确对应大型部件，最后 4 个大型部件对应终极工程。
- `blueprint`、`ready`、`completed` 三种状态稳定。
- 缺失配方和未知章节不会导致模型崩溃。
- 作品模型不修改背包、奖励账本和关卡进度。

浏览器测试：

- 完成普通关卡后显示当前作品卡和 12 节点路线。
- 跳过关卡显示蓝图/待装配状态，不误报成品。
- 实际合成组件后回到结算/背包显示成品视觉。
- 第 3、6、9、12 关显示阶段部件提示。
- 移动端、平板、桌面端无横向溢出。
- 减少动画和低性能模式下仍有清晰的作品状态和操作按钮。
- 现有奖励合并、继续下一关、返回地图、背包和合成流程保持通过。

发布校验继续运行：`npm test`、严格内容审核、游戏 UI 测试、响应式审计、低性能审计、构建、包体积检查和浏览器冒烟测试。

## 7. 验收标准

- 学生完成任意关卡后能立即看到与本关关联的独立作品。
- 未合成时看到的是明确的蓝图/材料进度，合成后才显示已完成。
- 作品展示有明显的视觉层级和成就反馈，但不干扰下一关操作。
- 所有现有章节和后续标准章节无需手工新增结算逻辑即可适用。
- 全量测试和发布门禁通过，且工作区既有无关改动不被覆盖。
