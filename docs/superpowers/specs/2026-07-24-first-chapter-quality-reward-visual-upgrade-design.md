# 首章题目质量、战术复盘、奖励经济与物品视觉升级设计

**日期：** 2026-07-24
**状态：** 用户已确认设计，待实施计划审阅
**适用范围：** 当前纯闯关版第一章“启程试炼”，共 12 个知识点关卡、每关 10 题。
**设计关系：** 本文是 `2026-07-22-knowledge-quest-game-design.md` 的增量升级。涉及题目重写、随机奖励、战术复盘和图片资产的条款以本文为准；原文中与本文冲突的“题目不重写”“不使用随机掉落”“不展示解析”“不引入图片资源”等限制不再适用。

## 1. 目标与原则

本轮升级同时解决三个问题：

1. 题目难度不能只靠标签和数字大小，必须体现可审查的思维递进。
2. 学生答对或跳过后应能理解解法，但解析不能破坏“答题 → 奖励 → 继续”的游戏节奏。
3. 随机掉落可以制造惊喜，但不能因运气不足阻止玩家完成 J-20 超级工程。

长期原则：

- 知识点仍是关卡骨架，每关严格 10 题。
- 任何一次答错都只显示“再试一次 / 跳过”，不提前泄露答案。
- 主线工程材料确定获得，随机奖励只提供额外价值。
- 故事情境服务数学关系，不给裸算式机械添加背景名词。
- 物品图标使用原创高写实微缩模型，不模仿 Minecraft 图标或其他现有游戏素材。
- 背包、奖励领取记录、关卡进度和复盘状态均需支持版本迁移。

## 2. 第一章工程叙事

12 个知识点保持现有顺序，每三个知识点服务一个大型部件：

| 阶段 | 知识点 | 工程场景 | 大型部件 |
| --- | --- | --- | --- |
| 结构设计 | 找规律、巧算与凑整、等差数列与配对求和 | 计算机身尺寸、排列与材料用量 | 机身结构部件 |
| 控制系统 | 周期问题、有序枚举、加法与乘法原理 | 安排控制信号、测试次序与路线 | 航电雷达部件 |
| 飞行测试 | 容斥初步、和差倍、归一归总 | 整理探测数据和飞行参数 | 隐身机翼部件 |
| 动力调试 | 盈亏、鸡兔同笼、平均数 | 分配能源并分析测试结果 | 矢量动力部件 |

场景采用航空科技、工程实验和探索任务，不引入战斗、攻击或超出目标年龄的军事术语。每一阶段结束后，蓝图点亮约 25%。

## 3. 每关十题的认知曲线

每个知识点必须按固定题位承担不同思维任务：

| 题位 | 认知任务 | 内容约束 |
| --- | --- | --- |
| 1 | 识别核心概念 | 单一条件、直接表示 |
| 2 | 直接应用 | 完成一次标准方法 |
| 3 | 改变表示 | 在语言、数列、表格等表示间切换 |
| 4 | 逆向推理 | 由结果反求条件或起点 |
| 5 | 增加有效条件 | 比前题多一个需要处理的约束 |
| 6 | 两步推理 | 需要连续完成两个逻辑步骤 |
| 7 | 场景应用 | 数据与真实生活或工程情境有直接关系 |
| 8 | 方法辨析 | 识别易混方法或排除不适用方法 |
| 9 | 跨情境迁移 | 在新表示或新场景中调用同一知识 |
| 10 | Boss 综合任务 | 选择方法、完成推理并验证答案 |

难度由以下维度共同决定：

- 推理步骤数；
- 有效条件数；
- 正向或逆向推理；
- 表示形式；
- 数字复杂度；
- 是否需要选择方法；
- 是否需要验证结果。

禁止仅替换数字生成多道同模板题。题目质量验证器应能报告疑似模板重复，最终由人工审题确认。

## 4. 题目数据模型

现有题目字段继续保留，新增结构化质量字段：

```js
{
  id: "patterns-03",
  title: "扫描范围",
  prompt: "雷达扫描范围依次为 3、6、12、24 千米，下一轮是多少千米？",
  answer: "48",
  acceptedAnswers: ["48千米"],
  difficulty: "进阶",
  slot: 3,
  learningObjective: "识别倍增规律",
  reasoningType: "观察并归纳",
  difficultyProfile: {
    steps: 1,
    conditions: 1,
    representation: "sequence",
    direction: "forward",
    transfer: "direct"
  },
  storyBeat: "校准逐轮扩大的雷达扫描范围",
  solutionReview: {
    observation: "相邻两个数都扩大为原来的 2 倍",
    steps: [
      "6 ÷ 3 = 2，12 ÷ 6 = 2",
      "24 × 2 = 48"
    ],
    answer: "48 千米",
    check: "48 ÷ 24 = 2，仍符合相同规律",
    pitfall: "不要把它误认为每次增加相同的数"
  }
}
```

质量要求：

- `learningObjective` 只能表达一个主要目标；
- `reasoningType` 使用受控枚举；
- `difficultyProfile` 的步骤和条件数必须为正整数；
- `solutionReview.steps` 基础题为 1–2 步，Boss 题最多 5 步；
- `solutionReview.answer` 必须与判题答案一致；
- `check` 必须提供可执行的验算或逻辑复核；
- `pitfall` 必须指出真实易错点，不能使用空泛鼓励语。

### 4.1 挑战态数据边界

正式内容源可以保留答案、可接受答案、解析和复盘字段，但进入挑战页的运行态题目对象必须被裁剪为 `challengeQuestion`：

```js
{
  id: "patterns-03",
  title: "扫描范围",
  prompt: "雷达扫描范围依次为 3、6、12、24 千米，下一轮是多少千米？",
  difficulty: "进阶",
  slot: 3,
  learningObjective: "识别倍增规律",
  storyBeat: "校准逐轮扩大的雷达扫描范围",
  rewardPreview: ["radar-alloy"]
}
```

`challengeQuestion` 不包含 `answer`、`acceptedAnswers`、`hints`、`solutionReview` 或旧学习支持字段。答案判定和复盘读取只能通过受控接口完成：

- `judgeAnswer(questionId, userAnswer)`：读取完整内容源并返回是否正确，不返回标准答案；
- `resolveQuestion(questionId, resolution)`：在答对或跳过后写入 `resolved` 状态；
- `getResolvedReview(questionId)`：仅在当前题处于 `resolved` 状态时返回 `solutionReview`；
- 浏览器 UI state、localStorage 中的当前挑战态和地图态不得保存标准答案或复盘正文。

本项目是本地静态应用，无法阻止开发者从构建产物中逆向读取内容源；本条验收边界限定为“默认运行态和可见 UI 不提前暴露答案/复盘”，不把静态 bundle 视为安全边界。

### 4.2 人工审题评分表

每道正式题除自动校验外，还需要人工审题记录。评分表使用 0/1 制，6 项均通过才可进入内容快照：

| 项目 | 通过标准 |
| --- | --- |
| 目标单一 | 只考察一个主要知识点或方法 |
| 非模板重复 | 与同关其他题不只是替换数字 |
| 情境必要 | 情境与数量关系或问题目标直接相关 |
| 递进明确 | 题位对应的认知任务能被看出来 |
| 复盘可执行 | 步骤、答案和检查方法能独立复核 |
| 易错真实 | `pitfall` 指向学生可能真的犯的错 |

审题记录至少包含 `questionId`、6 项布尔值、审题人、审题时间和备注。自动质量验证器负责列出疑似问题，人工审题负责最终放行。

## 5. 故事情境标准

不要求每题都有完整故事：

- 第 1–4 题最多使用一句短任务背景；
- 第 5–8 题使用有效生活或工程情境；
- 第 9 题使用新的迁移情境；
- 第 10 题承担本关主要故事内容。

故事合格的判断标准是：删除情境后，题目中的数量关系或问题目标会失去具体意义。不得使用“工程师来到基地，请计算 125×24”一类装饰性包装。更合适的表达是“每个检测区记录 125 组数据，共有 24 个检测区，怎样快速算出数据总数”。

## 6. 战术复盘

用户已确认采用方案 A：答对或跳过后出现可折叠的“战术复盘”，默认不展开。

### 6.1 状态流

```text
作答中
├─ 答错 → 再试一次 / 跳过
└─ 答对或跳过 → 本题已解决
                    ├─ 展开战术复盘
                    └─ 继续下一题
```

任何错误提交都只显示“再试一次 / 跳过”。只有答对或主动跳过后，系统才进入 `resolved` 状态，并且不立即切换到下一题。

### 6.2 显示内容

默认状态只显示：

- 随机鼓励语；
- 本题实际获得的奖励；
- “展开战术复盘”；
- “继续下一题”。

展开后依次显示：

1. 关键观察；
2. 分步推理；
3. 正确答案；
4. 检查方法；
5. 易错提醒。

基础题保持短小；Boss 题允许 3–5 个步骤。复盘不使用长篇授课语气。

### 6.3 安全与持久化

- 学生作答前的 `challengeQuestion` 不得包含答案、可接受答案、提示或复盘字段。
- 只有 `resolved` 状态可以通过受控接口读取当前已解决题目的复盘。
- `resolved` 状态必须记录 `questionId`、`resolution`、`attemptId`、`resolvedAt` 和是否已进入下一题。
- 在复盘状态返回地图、打开背包或关闭应用后，重新进入仍能看到本题结果。
- 点击“继续下一题”后才清除上一题复盘状态。
- 跳过题进入 `resolved`，状态展示为“已看复盘，待补领奖励”；后续重玩并答对后才写入固定奖励领取记录。

## 7. 奖励经济

奖励拆成“确定成长”和“随机惊喜”两条轨道。

| 奖励层级 | 获取方式 | 作用 |
| --- | --- | --- |
| 固定材料 | 首次答对每道题 | 保证知识点组件可合成 |
| 随机掉落 | 答对进阶及以上题目后额外判定 | 收藏品、外观、催化剂和通用资源 |
| 连胜宝箱 | 连续答对 3、6、10 题 | 提供关内短期目标 |
| 满星奖励 | 一关 10 题全部答对 | 蓝图碎片、特殊徽章 |
| Boss 奖励 | 正确完成第 10 题 | 核心材料或专题纪念品 |
| 阶段奖励 | 完成每三个知识点 | 拼装大型部件 |

### 7.1 固定材料

- 每题首次答对领取一次固定材料。
- 每关 10 道题的首次固定材料总和应足够合成该关组件。
- 跳过不发放本题固定材料。
- 后续重玩并答对曾跳过的题，可补领尚未领取的首次奖励。
- 已领取的固定奖励不能通过重玩重复刷取。
- 领取记录以题目 ID 为稳定键并独立持久化。

固定材料、关卡组件和阶段大部件必须由一张可验证配置表串起来：

```js
{
  levelId: "patterns",
  componentId: "fuselage-frame-01",
  fixedRewards: [
    { questionSlot: 1, itemId: "carbon-fiber", quantity: 1 },
    { questionSlot: 2, itemId: "titanium-rib", quantity: 1 }
  ],
  componentRecipe: [
    { itemId: "carbon-fiber", quantity: 2 },
    { itemId: "titanium-rib", quantity: 2 }
  ],
  stagePartId: "fuselage-structure",
  stageRecipe: [
    { itemId: "fuselage-frame-01", quantity: 1 },
    { itemId: "quick-calc-frame-02", quantity: 1 },
    { itemId: "sequence-frame-03", quantity: 1 }
  ]
}
```

配置不变量：

- 每关 10 个 `questionSlot` 均有且只有一条固定奖励配置；
- 关卡组件配方所需材料数量不得超过该关 10 题首次答对可获得数量；
- 阶段大部件配方只依赖本阶段 3 个关卡组件；
- 最终 J-20 配方只依赖 4 个阶段大部件；
- 校验器必须从空库存模拟“120 题全部首次答对”，并证明最终 J-20 可组装。

### 7.2 随机掉落

- 随机掉落是固定材料之外的额外判定。
- 题目难度越高，可获得的品质上限越高。
- 随机池仅包含工程收藏品、外观、合成催化剂和未来系统使用的通用资源。
- 随机物品不能替代主线组件，不能决定是否可以完成章节。

引入可见的“幸运能量”：连续未获得稀有奖励时逐步增加，达到阈值后下一次必定掉落稀有物品，随后清零。保底状态必须持久化。

随机结算必须可追踪且幂等：

- 每次答对或跳过生成稳定 `attemptId`，同一次 `attemptId` 只能结算一次随机事件；
- 跳过不触发随机掉落，也不改变幸运能量；
- 重玩并再次答对可以触发新的随机事件，但必须生成新的 `attemptId`；
- 随机结果、幸运能量变更和奖励入库必须在同一结算事务中完成；
- 刷新页面、返回地图、重复点击“继续下一题”不得重复发放随机奖励；
- 随机池条目必须声明 `itemId`、`rarity`、`minDifficulty`、`weight`、`purpose`，其中 `purpose` 不得为 `mainline-required`。

### 7.3 连胜与展示节奏

- 连续答对 3 题：普通补给箱；
- 连续答对 6 题：精良补给箱；
- 连续答对 10 题：完美作战箱。

答错只中断当前连胜，不扣除已有物品或星级。跳过后可继续关卡，但不能获得本轮完美箱。

普通固定材料使用轻量“飞入背包”反馈，不阻塞答题。只有稀有及以上掉落、连胜宝箱、组件完成、大型部件拼装和最终战机完成使用完整揭晓画面。

### 7.4 阶段状态

第 3、6、9、12 关结算时根据真实库存显示：

- 材料齐全：大型部件可以拼装；
- 材料不足：显示缺少的物品和数量；
- 有题未领取：提供对应题目的补领入口；
- 已拼装：显示部件完成状态。

不得再无条件显示“材料已就绪”。首轮 120 题全部首次答对后，最终 J-20 可组装概率必须为 100%。

## 8. 物品视觉升级

用户已从视觉对比中选择 A“高写实微缩模型”方案，替换现有抽象物品图标。

### 8.1 替换范围

共 28 个核心物品：

- 11 个原材料；
- 12 个 J-20 中间组件；
- 4 个大型部件；
- 1 个最终 J-20 战机。

正常物品不再使用现有抽象 SVG。代码生成 SVG 仅作为未知或加载失败物品的通用兜底。

### 8.2 视觉规范

- 原创高写实微缩模型；
- 三分之四俯视角，主体居中；
- 真实木材、矿石、宝石、金属和航空合金材质；
- 左上方柔和工作室主光；
- 暖色中性工作台背景；
- 深蓝、金色仅作为少量界面装饰；
- 同类别物品保持统一镜头、光线和比例；
- 不使用像素、方块或体素造型；
- 不模仿 Minecraft 或其他游戏的图标构图；
- 图片本身不包含品质边框、文字、标志或水印。

品质边框、数量、可合成状态和锁定状态由 CSS 叠加，避免资源与数值配置耦合。

### 8.3 资源规格

- 原材料和中间组件：256×256 WebP；
- 大型部件：512×512 WebP；
- 最终战机和合成庆典：1024×1024 或适配庆典布局的高清横图；
- 背包图片使用延迟加载；
- 当前题目奖励和即将揭晓的稀有资源可提前加载；
- 所有图片必须具有中文替代文本；
- 48–64 像素显示时仍能快速区分轮廓和材质。

生产图片使用完整的中性背景，不依赖透明通道。这样可以稳定呈现金属、宝石和反射材质，同时降低复杂抠图造成的边缘瑕疵。

图片资源通过 `itemVisuals` manifest 接入，避免散落在组件代码中：

```js
{
  itemId: "carbon-fiber",
  src: "/assets/items/carbon-fiber.webp",
  width: 256,
  height: 256,
  alt: "碳纤维材料的高写实微缩模型",
  fallbackIcon: "material-generic",
  preloadPriority: "current-reward"
}
```

manifest 要求：

- 28 个核心物品必须全部有 `src`、尺寸和中文 `alt`；
- `itemId` 必须存在于物品目录，禁止出现孤立图片；
- 图片加载失败时使用 `fallbackIcon`，并保留物品名称和数量文本；
- 背包列表使用懒加载，当前题奖励、稀有揭晓和阶段拼装资源可预加载；
- CSS 负责品质边框、锁定状态、数量角标和可合成状态，图片文件不承载这些状态。

## 9. 实施阶段

### 阶段一：题目与复盘基础

- 扩展题目模型；
- 增加 `challengeQuestion` 裁剪层和受控判题/复盘接口；
- 增加 `resolved` 状态；
- 实现可折叠战术复盘；
- 保存和恢复复盘状态；
- 增加答案泄露保护测试。

### 阶段二：120 道题质量升级

- 按十题认知曲线重审全部题目；
- 优先改造当前解析和辅助字段覆盖较弱的找规律、和差倍和鸡兔同笼；
- 补齐全部结构化复盘；
- 重写 12 道 Boss 题的综合工程场景；
- 建立自动质量验证器和人工审题评分表；
- 将人工审题结果纳入内容快照，缺失或未通过时阻断发布。

### 阶段三：奖励经济重构

- 分离首次固定奖励与额外随机掉落；
- 建立首次领取记录；
- 建立固定材料、组件、阶段大部件和最终 J-20 的配方配置；

## 10. 验收指标

- 12 个关卡均严格包含 10 道题。
- 120 道题均具备完整的结构化复盘。
- 120 道题均具备人工审题记录，6 项评分全部通过。
- 每关题位符合约定认知曲线。
- 默认运行态和可见 UI 中，作答前答案和复盘泄露数量为 0。
- 答对和跳过后可以查看复盘；任意次数答错后仍只有“再试一次 / 跳过”。
- 复盘状态在返回、打开背包和重新启动后可恢复。
- 跳过不发放本题奖励，不写入掌握记录；重玩答对后可补领。
- 首次固定奖励不可重复领取，漏领奖励可以通过重玩补领。
- 从空库存模拟 120 题全部首次答对时，固定材料、关卡组件、阶段大部件和最终 J-20 配方全部可满足。
- 首轮全部首次答对后，完成 J-20 的概率为 100%。
- 随机掉落不参与主线组件的必要配方。
- 随机掉落按 `attemptId` 幂等结算，刷新或重复点击不会重复发奖。
- 阶段提示与真实库存一致。
- 28 个核心物品全部使用高写实微缩模型图片。
- 28 个核心物品全部存在于 `itemVisuals` manifest，且 `itemId`、尺寸、中文 `alt` 与兜底图标完整。
- 物品在 48–64 像素下可辨识，加载失败时有可访问兜底。
- 游戏版本升级后，背包、奖励领取、幸运能量、关卡和复盘状态均能迁移。
