# 题目质量专项审查报告

审查时间：2026-08-13 08:34

## 审查范围与证据

- 范围：9 章、108 个知识点、1080 道题；重点检查知识点匹配、难度递进、情境必要性、解题复盘和质量门禁。
- `npm test`：179/179 通过。
- `npm run check`：通过。
- `npm run validate:game`、`npm run validate:release`：均通过，9 章人工审核清单均为 `approved`。
- 全量统计：每章 120 题；第 7～9 章 360 题全部由 `methodQuestionPackFactory` 生成。
- 抽样：每章抽取第 1、6、12 个知识点的基础、进阶、挑战题，并统计答案格式、题干长度、难度步数、条件数、迁移类型和运算复杂度。

## 严重问题

### 1. 第 7～9 章是单算式模板换数字，难度标签没有对应真实难度

- 位置：`game/methodQuestionPackFactory.js:33-248`、`game/methodQuestionPackFactory.js:252-269`
- 每个 `methodId` 只有一个 `solve` 分支；10 个题位只改变数值和通用场景前缀。第 7、9 章从基础到挑战的解释运算符平均数完全相同；第 8 章也几乎不变。
- “审题与提取条件”10 题均为“箱数×每箱数量+备用”；“综合生活建模 Boss”10 题均为“组数×每组数量+公共数量”。第 1 题和第 10 题只是数字不同。
- 学生练到的是代数值，而不是审题、建模和迁移；“挑战/Boss”仅是标签。
- 建议：每个知识点至少设计 5 类数学结构变式；题位 1～10 按“识别—单模型—逆向—条件扰动—开放策略—综合迁移”递进。

### 2. 多个知识点名称与实际解题行为不匹配

- 位置：`game/methodQuestionPackFactory.js:142-174`、`game/methodQuestionPackFactory.js:220-248`
- “统筹安排”实际是三个时长直接相加；“最短路线”是横纵步数相加；“最优策略”只求两个耗时之差；“构造法”只是矩形周长；“反证启蒙”只是平均分；“运动与变化建模”只是路程=速度×时间。
- 这会使课程地图、学习反馈和能力判断失真。
- 建议：建立“知识点—必要认知动作”契约。例如统筹题必须存在可并行或可穿插任务，最短路线必须存在多个候选路径，反证题必须从假设推出矛盾。

### 3. 难度画像由题位机械生成，可把简单题包装成多步 Boss 题

- 位置：`game/chapterBuilder.js:27-92`、`game/chapterQualityProfiles.js`
- `difficultyProfile`、`transferType` 和 `solutionReview` 主要由 slot 生成，未根据题目条件、所需模型或实际推导校验。
- 第 7～9 章虽然元数据显示挑战题 3～4 步、`boss-integration`，实际题式与基础题相同。
- 建议：每题显式声明 `requiredConcepts`、`reasoningMoves`、`conditionRoles`、`representationShift`，门禁根据内容约束难度。

### 4. 人工审核门禁形成了错误安全感

- 位置：`game/questionQuality.js:105-121`、`scripts/validate-game-content.js:54-70`、`content/humanReview/chapter-07.json` 至 `chapter-09.json`
- 清单只要求六项分数都等于 1，并校验内容哈希；第 7～9 章所有题均标记 `contextNecessary=1`、`progressionClear=1`。
- 但“工坊日志/校准表/终点报告”等外壳删除后数学条件不变，基础到挑战也没有实质递进，审核结果与题目事实矛盾。
- 建议：审核记录增加证据字段和驳回原因；自动门禁先产出客观指标；内容变更后不得沿用旧的全 1 评分。

## 建议修改

### 5. 缺少统一的年级与能力层级约束

- `data.js` 的旧模块带 `grades`，但 `game/chapterBuilder.js:99-105` 构建关卡时不保留年级；第 4～9 章原生题包也未声明年级。
- 建议按 3～4 年级启蒙、4～5 年级进阶、5～6 年级竞赛预备组织知识图谱；每题标注最低年级、核心方法、计算负担和阅读负担。

### 6. “模板多样性”统计的是文案外壳，不是数学结构

- 位置：`game/methodQuestionPackFactory.js:15-29,252-269`、`game/questionQuality.js:78-103`
- 第 7～9 章的 5 个 `templateFamily` 来自五个通用引导语；重复检测仅替换数字，换几个词即可绕过。
- 建议增加数学结构指纹：运算树、条件角色、问题方向、表示方式、答案域和所需策略；挑战题不得与基础题同指纹。

### 7. 复盘结构齐全，但大量内容只是通用话术加原 explanation

- 位置：`game/chapterBuilder.js:66-89`、`game/chapterQualityProfiles.js`
- 第 4～6 章每章 120 题分别只有 2、4、3 类 observation/method/pitfall 组合；复盘步数随题位增加，却不保证每一步是真实推理。
- 建议把解题过程改为题目自带、可复算的步骤 AST，包含条件使用理由、模型成立原因、逐步计算、替代验证和真实易错分支。

### 8. 答案契约只保证可判定，没有覆盖小学奥数表达规范

- 位置：`game/questionContract.js`、`game/methodQuestionPackFactory.js:208-212`
- 概率题可直接发布 `2/6` 等未约分答案；数值输入不要求最简分数、余数表达或多问结果。
- 建议增加 `answerPolicy`，支持最简分数、带余数、多个数值、顺序无关结果和单位约束，同时保持自动判定。

## 亮点

- 1080 道题均有稳定 ID、可自动判定答案、结构化复盘和固定难度槽位。
- 构建、奖励、存档、章节注册和发布校验已有较强回归测试，适合在不破坏游戏系统的前提下替换内容层。
- 第 1～3 章已有一批真正包含奥数模型的题目，可作为第 7～9 章的内部质量样例。
